**Date:** 2026-06-10
**Scope:** Full repo — 162 Luau files, ~45,500 lines (`src/client`, `src/server`, `src/shared`, `src/replicatedFirst`), plus the vendored ByteNet networking backbone in `Packages/`.
**Focus:** Mobile performance, logic bugs, Luau quality, server-side security.

## 1. SECURITY (server-side)

### S1. `WeaponHit` trusts client-supplied hit payload — max-damage / guaranteed-headshot exploit
- **File:** `src/server/WeaponsSystem/NetworkingCallbacks.luau:172-199`, `src/server/WeaponsSystem/WeaponTypes/BulletWeapon.luau:850,868`, `src/server/WeaponsSystem/WeaponsSystem.luau:958`, `src/server/WeaponsSystem/Libraries/WeaponSecurity.luau:106-214`
- **Severity:** Critical | **Category:** Security
- `WeaponSecurity.validateHit` only checks a cone/range on `hitInfo.p`. The server then (a) resolves the victim humanoid from **client-chosen** `hitInfo.part` — sending the victim's `Head` always grants the 2× headshot multiplier; (b) uses **client-chosen** `hitInfo.d` for damage falloff — sending `d = 0` always yields max damage; (c) never checks that `hitInfo.p` is near `hitInfo.part`'s real position. The cone check allows a 60° spread (`MIN_DIR_DOT = 0.5`), and `hitsRemaining` from `NumProjectiles` lets one legit `fireInfo` be cashed in as N headshots.
- **Fix:**
```luau
-- WeaponSecurity.validateHit, after the range check:
if typeof(hitInfo.part) ~= "Instance" or not hitInfo.part:IsA("BasePart") then
	return false, "bad part"
end
if (hitInfo.part.Position - hitInfo.p).Magnitude > hitInfo.part.Size.Magnitude + 5 then
	return false, "part/point mismatch"
end
-- BulletWeapon:applyDamage — never trust hitInfo.d:
local damage = self:calculateDamage((hitInfo.p - data.origin).Magnitude)
```
Accept headshots only when `hitInfo.part.Name == "Head"` **and** the part/point check passes; tighten `MIN_DIR_DOT`; ideally add a server raycast for line-of-sight.

### S2. `HealthPickupService` heals on unvalidated client claim — combat god-mode
- **File:** `src/server/features/match/HealthPickupService.luau:54-78` (heal at 44-52, cooldown at 31)
- **Severity:** Critical | **Category:** Security
- The handler validates only `data.kind == "Health"`, round-active, and not-in-menu. There is no check that a pickup entity exists, was near the player, or was consumed. A modified client can fire `Network.Match.RequestPickup{kind="Health"}` every `0.2s` (the only throttle) and regenerate +30 HP indefinitely.
- **Fix:** track dropped pickups server-side (id, position, claimed flag); require the pickup id in the request and validate existence, unclaimed state, and player range before healing:
```luau
local pickup = _activePickups[data.id]
if not pickup or pickup.claimed then return end
local root = character:FindFirstChild("HumanoidRootPart")
if not root or (root.Position - pickup.position).Magnitude > PICKUP_RADIUS then return end
pickup.claimed = true
_applyHealthPickup(character)
```

### S3. `/resetdata` command enabled in production — `IsServer()` is always true
- **File:** `src/server/features/testing/ClearDataCommandService.luau:15` (auth at 25-34)
- **Severity:** Critical | **Category:** Security
- `local ENABLE_CLEAR_COMMAND = RunService:IsStudio() or RunService:IsServer()` — on any live server `IsServer()` is `true`, so the "testing-only" guard is a no-op and the data-wipe command surface exists in production. It is still gated to `ALLOWED_USER_IDS`, so it is not open to all players, but the intended safety switch is defeated.
- **Fix:** `local ENABLE_CLEAR_COMMAND = RunService:IsStudio()`.

### S4. `WeaponReloadRequest` / `WeaponReloadCanceled` have no ownership check — reload griefing
- **File:** `src/server/WeaponsSystem/NetworkingCallbacks.luau:127-140, 157-170`
- **Severity:** High | **Category:** Security
- Unlike `WeaponFired`/`WeaponActivated`, these never check `weapon.player == player`. Any client can force `reload()` on **another player's** weapon server-side (`BaseWeapon.luau:934-962`), setting `IsReloading=true` (blocking the victim's fire) and broadcasting a fake reload. Also `weaponType.CanBeReloaded` (line 136) is indexed without the `weapon and weaponType` guard the other handlers use.
- **Fix:**
```luau
if weapon and weaponType and weapon.instance == instance
	and weaponType.CanBeReloaded and weapon.player == player then
	weapon:reload(player, true)
end
```

### S5. Respawn cooldown is client-enforced
- **File:** `src/server/features/match/MatchService.luau:1952-1998` (esp. 1962-1964)
- **Severity:** High | **Category:** Security / Logic
- The server enforces only a 0.5s floor; the real `GameConfig.RespawnCooldown` runs client-side in the death screen. A modified client can respawn every 0.5s.
- **Fix:** record `deathAt` per player and require `time() - deathAt >= GameConfig.RespawnCooldown` server-side.

### S6. ByteNet read loop crashes on malformed client buffers (no pcall, no rate limit)
- **File:** `Packages/_Index/howmanysmall_bytenet@0.4.7/bytenet/src/process/read.luau:39-50`, `.../server.luau:44-52`
- **Severity:** Medium | **Category:** Security
- A client firing `ByteNetReliable` with an arbitrary buffer makes `ref[id]` nil or `packet.Reader` throw, aborting the **whole batch** (dropping co-batched legit packets) and spamming server errors for free. There is also no packets-per-batch cap or network-layer rate limit (service cooldowns fire only *after* deserialization).
- **Fix:** in the read loop, `local packet = ref[id]; if not packet then return end` and wrap `packet.Reader` in `pcall`, discarding the rest of the buffer on failure. Add a shared `NetGuards.rateLimit(player, key, perSecond)` token bucket.

### S7. `NetGuards` validates strings only — no numeric validation layer
- **File:** `src/shared/networking/NetGuards.luau:32-67`
- **Severity:** High (structural) | **Category:** Security
- The shared guard layer cannot express NaN/±inf/negative/integer constraints, yet C→S packets carry Float32/Int32 fields (`Settings.UpdateSlider.value`, `Settings.UpdateColor.r/g/b`, `BattlePass.ClaimTier.tier`). Current handlers each hand-roll the checks (verified: SettingsService NaN check + clamp; BattlePassService floor + range), so nothing is exploitable **today**, but any future numeric field is unprotected by default.
- **Fix:** extend the schema with typed rules:
```luau
local function validNumber(v: any, rule): boolean
	if type(v) ~= "number" or v ~= v or v == math.huge or v == -math.huge then return false end
	if rule.integer and v % 1 ~= 0 then return false end
	if rule.min and v < rule.min then return false end
	if rule.max and v > rule.max then return false end
	return true
end
```
Also cheap: `if utf8.len(value) == nil then return false end` for strings forwarded to Roblox web APIs (`Gifting.ValidateUser.username`, `Rewards.RedeemCode.code`).

## 2. MOBILE PERFORMANCE

### P1. Animated wrap textures keep scrolling every Heartbeat after Locker / Battle Pass close
- **Files:** `src/client/features/locker/init.luau:1624-1639` (`closeLockerGui` never clears the grid), `src/client/features/battlepass/init.luau:308-321, 416-476, 609-637, 800-804` (`onClose` never releases wraps), `src/client/features/locker/Previewers/WeaponWrapPreviewer.luau:98-117`
- **Severity:** High | **Category:** Mobile performance / leak
- Every animated wrap viewport (6 `Texture` instances each) registers in `WeaponWrapPreviewer`'s module-level Heartbeat loop and is only released when the wrap *changes* or the feature is torn down — not when the panel closes. After one browse of the Wraps tab or Battle Pass page, dozens of invisible textures get `OffsetStudsU/V` written **every frame for the rest of the session**. Additionally `WeaponWrapPreviewer`'s loop lacks the 30 Hz touch-device throttle that `WeaponWrapAnimator.luau:41-43,125-133` already has, and re-reads `StudsPerTileU/V` per texture per frame.
- **Fix:** in `closeLockerGui` call `grid:Clear()` (cards are pooled — reopen stays cheap); in battlepass `onClose` clear `wrapBySlot` + preview wrap; apply the same `TouchEnabled → 1/30s` accumulator and tile-size caching in `WeaponWrapPreviewer`.

### P2. Loading screen: per-frame layout writes, serialized over-broad preload, forced 6s minimum
- **File:** `src/replicatedFirst/LoadingScreen.client.luau:23, 42-52, 71-104, 109-130`
- **Severity:** Medium | **Category:** Mobile performance
- `RenderStepped` rewrites `textFilled.Position/Size` every frame for the whole load; the preload list is *every* MeshPart/Decal/Texture in the Lobby plus every menu image, each in its own serialized `ContentProvider:PreloadAsync({asset})` call; `MIN_LOAD_TIME = 6` forces a 6s wait even when cached.
- **Fix:** drive the text mask from `titleContainer:GetPropertyChangedSignal("AbsoluteSize")`; preload only above-the-fold assets in small batches; lower/remove the artificial minimum.

### P3. Projectile simulation: up to 50 penetrate-raycast tries per sample per frame
- **Files:** `src/server/WeaponsSystem/WeaponTypes/BulletWeapon.luau:606-828`, `src/server/WeaponsSystem/Libraries/Parabola.luau:131`
- **Severity:** High | **Category:** Mobile performance
- Non-hitscan shots raycast every Heartbeat for up to `MAX_BULLET_TIME = 4s`; the penetrate loop caps at **50 tries** per sample (vs 8 in ShoulderCamera). A shotgun (`NumProjectiles=8`) on auto-fire is the worst case. The hitscan path used for mobile auto-fire mitigates this, but manual fire still pays it.
- **Fix:** cap Parabola's penetrate tries at 8 and reduce `MAX_BULLET_TIME` for fast bullets.

### P4. 20 Hz auto-aim full-workspace scan
- **Files:** `src/server/WeaponsSystem/Libraries/BaseWeapon.luau:705-745`, `src/server/WeaponsSystem/Libraries/AutoAimSystem.luau:57-143`
- **Severity:** Medium | **Category:** Mobile performance
- `findBestTarget` iterates `workspace:GetChildren()` + nested Bots folders + per-candidate `WorldToViewportPoint` + 2 raycasts, 20×/sec, while a weapon is equipped. Buffers are reused (good), but the candidate *discovery* doesn't need 20 Hz.
- **Fix:** cache the candidate character list and refresh it at 2–4 Hz (or on CharacterAdded/Removed events); keep only scoring/raycasts at 20 Hz. The mobile shotgun crosshair raycast (`Gui/Crosshair.luau:182`, 10 Hz) could share these results.

### P5. DepthOfField + 18px Blur stacked in the lobby on all devices
- **Files:** `src/client/core/lighting/DepthOfFieldController.luau:23-28`, `src/client/features/match/init.luau:172-183`, `src/client/core/ui/BlurController.luau` (`BLUR_SIZE = 18`)
- **Severity:** Medium | **Category:** Mobile performance
- DOF is force-enabled in Lobby/ReturningToMenu and panel blur stacks on top — two full-screen post effects exactly where mobile players idle.
- **Fix:** gate on device class:
```luau
local isMobile = UserInputService.TouchEnabled and not UserInputService.MouseEnabled
DepthOfFieldController.setEnabled(inMenu and not isMobile)
```

### P6. `UISoundsController` retains every button ever created — unbounded growth
- **File:** `src/client/core/ui/UISoundsController.luau:55-72, 80-95`
- **Severity:** Medium | **Category:** Memory leak
- Every `GuiButton` entering `PlayerGui` becomes a **strong key** in `boundSet` plus a janitor entry, never removed. The locker rebuilds nav buttons on every category switch (`locker/init.luau:808-812`); kill-feed/vote/notification clones add more. Destroyed instances can't GC; the janitor list grows all session.
- **Fix:** weak keys + per-button cleanup:
```luau
local boundSet: { [GuiButton]: boolean } = setmetatable({}, { __mode = "k" }) :: any
```
and disconnect on `button.Destroying` instead of accumulating in the module janitor.

### P7. ByteNet per-player channels leak on PlayerRemoving
- **File:** `Packages/_Index/howmanysmall_bytenet@0.4.7/bytenet/src/process/server.luau:16-17, 54-62, 87-140`
- **Severity:** High | **Category:** Memory leak (server)
- `perPlayerReliable`/`perPlayerUnreliable` are populated on `PlayerAdded` but never cleared — each departed player leaks two channel tables (with possibly grown buffers) and pins the `Player` instance as a key. `SendTo` to a departed player writes into a channel that is never flushed.
- **Fix (vendored file, inside `serverProcess.start`):**
```luau
Players.PlayerRemoving:Connect(function(player)
	perPlayerReliable[player] = nil
	perPlayerUnreliable[player] = nil
end)
```

### P8. Kill/heal effect burst spawns
- **Files:** `src/server/WeaponsSystem/Libraries/BonusEffect.luau:291-331` (40 unanchored colliding coin parts per qualifying streak), `src/server/WeaponsSystem/Libraries/HealEffect.luau:203-230` (~45 ImageLabels per heal, no concurrent cap), `src/server/WeaponsSystem/Libraries/DirectionalIndicatorGuiManager.luau:106, 135-142` (cloned DI frames can leak if fade never reaches transparency 1; uses legacy `wait()`)
- **Severity:** Medium | **Category:** Mobile performance / leak
- Burst Instance/physics churn during the most action-heavy moments. The DI manager is also the repo's only remaining legacy `wait()` call.
- **Fix:** cap concurrent heal particles; reduce coin count (or anchor sooner) on `TouchEnabled`; clean DI clones on `Tween.Completed` + replace `wait()` with `task.wait()`.

### P9. `WeaponsGui` per-frame full rescale when `_uiReady` is stuck false
- **File:** `src/server/WeaponsSystem/Libraries/WeaponsGui.luau:356-360` (and re-enable bug at 323-326, see L7)
- **Severity:** Medium | **Category:** Mobile performance
- If the viewport is 0 during a transition, the render loop calls `onScreenSizeChanged` → recursive `updateScale` over the whole scaling tree **every frame** until ready. Debounce or cap retries.

### P10. BotAI is the dominant server cost (scaling note)
- **File:** `src/server/AI/BotAI.luau:819-835, 881-1118`
- **Severity:** Medium | **Category:** Server performance
- ~3 coroutines per bot at 10–20 Hz with up to 3 LoS raycasts per eval (~240 raycasts/sec at 8 bots). The code is already heavily optimized (cached refs, buffer reuse, FOV pre-filter, distance-squared early-out) — flagged as the main scaling risk if bot counts grow, not a bug. `PathfindingQueue` (budgeted FIFO) is well done.

## 3. LOGIC BUGS

### L1. Loading screen never dismisses if Lobby/Menu fail to replicate
- **File:** `src/replicatedFirst/LoadingScreen.client.luau:71-89, 109` (also 55-57: untimed AbsoluteSize spin-wait)
- **Severity:** Critical | **Category:** Logic
- If `workspace:WaitForChild("Lobby", 10)` and `playerGui:WaitForChild("Menu", 5)` both time out (precisely the flaky-mobile-network case), `assets` is empty, `totalAssets = 1`, `loadedAssets` stays 0, and `while loadedAssets < totalAssets` spins forever — the player is permanently stuck.
- **Fix:** `if #assets == 0 then loadedAssets = totalAssets end`, and add a hard overall timeout that dismisses the screen.

### L2. `GlobalKillFeed:Destroy()` errors and leaks its network listener
- **File:** `src/client/features/match/GlobalKillFeed.luau:331-334`
- **Severity:** High | **Category:** Logic bug + leak (also a `.` vs `:` mistake)
- `Network.Combat.KillFeed.Listen()` returns a plain disconnect **function** (ByteNet API), but the code calls `self._connection.Disconnect()` — indexing a function throws, the listener is never disconnected (it keeps cloning entries into a destroyed GUI on every kill), and the error aborts MatchHud's janitor teardown chain.
- **Fix:**
```luau
if self._connection then
	self._connection() -- ByteNet Listen returns a disconnect function
	self._connection = nil
end
```

### L3. ByteNet client namespace replication race can kill all networking on join
- **File:** `Packages/_Index/howmanysmall_bytenet@0.4.7/bytenet/src/replicated/values.luau:30-58` (triggered by every `DefineNamespace` in `src/shared/networking/Network.luau`)
- **Severity:** High | **Category:** Race condition
- The client resolves per-namespace `StringValue`s with `FindFirstChild` (no wait); if a client requires `Network` before the value replicates, the require errors and **all networking is dead for that session**. `values.start()` only waits for the parent folder.
- **Fix:** use `valueFolder:WaitForChild(name, 10)` in `values.access` (client branch) and error loudly if nil.

### L4. `doDamage` indexes nil `dealer` for ownerless explosion damage
- **File:** `src/server/WeaponsSystem/WeaponsSystem.luau:1049` (called from `BulletWeapon.luau:917` with `dealer = self.player`, which can be nil)
- **Severity:** High | **Category:** Logic
- `dealer:IsA("Player")` errors when `dealer` is nil (world-mounted/NPC weapon explosions).
- **Fix:** `if target:IsA("Humanoid") and dealer and dealer:IsA("Player") and dealer.Character then`.

### L5. Battle Pass items shown as purchasable but server always rejects — config contradiction
- **Files:** `src/shared/constants/ItemsConfig.luau:177, 182, 185, 189, 198-199` vs `src/shared/constants/BattlePassConfig.luau:115-124`; enforcement `src/server/features/shop/ShopService.luau:189`; client gate `src/client/features/locker/LockerCatalog.luau:151, 188`
- **Severity:** High | **Category:** Logic / cross-config inconsistency
- `BattlePassConfig.IsBPExclusive` derives exclusivity from tier membership, so `Gravity`, `Face2/5/9`, `Hat2/3` are unbuyable server-side — but only `Wrap_RPG_Blue` carries the `isBPExclusive` flag the client checks. Those six items render purchasable with a price and every purchase fails.
- **Fix:** mark all six `isBPExclusive = true, CanPurchase = false` in ItemsConfig, or make `LockerCatalog` call `BattlePassConfig.IsBPExclusive` like the server.

### L6. Phantom `Faces.Default` — default face silently no-ops
- **Files:** `src/shared/constants/ItemsConfig.luau:180-194` (no `Default` key) vs `src/shared/constants/DataTemplate.luau:309, 326`, `src/shared/constants/ItemDefaults.luau:6-8`; no-op at `src/shared/Locker/CosmeticsTemplates.luau:162-164`
- **Severity:** High | **Category:** Logic / cross-config inconsistency
- Every new player owns and equips `Faces.Default`, which doesn't exist in the catalog — `applyFaceToHead` silently does nothing and the Locker can never show the equipped face.
- **Fix:** add a real `Faces.Default` entry, or default the template to `Face1` and grant it.

### L7. `WeaponsGui.setEnabled(false)` permanently destroys rescale handlers
- **File:** `src/server/WeaponsSystem/Libraries/WeaponsGui.luau:151-157, 323-326`
- **Severity:** Medium | **Category:** Logic
- Disable disconnects **all** connections including `AbsoluteSize`/`CurrentCamera`/`GuiEnabled` watchers that are created only once in the constructor; re-enable restores only render/input. After one disable→enable cycle the GUI never rescales on resolution/camera changes.
- **Fix:** keep lifetime watchers in a separate connection list from the enable-scoped ones.

### L8. `ShoulderCamera.setEnabled(true)` can half-initialize when camera is momentarily nil
- **File:** `src/server/WeaponsSystem/Libraries/ShoulderCamera.luau:302-317`

### L9. `BaseWeapon` reload state machine: `canReload` never restored on completion; exact-equality ammo check

### L10. `Roblox.findInstanceImpl` infinite loop on final path segment

### L11. Music volume slider race — `LobbyMusic` resolved before the music feature creates it

### L12. `DeathScreenView` show/hide tweens are no-ops

- **Severity:** Medium | **Category:** Logic (dead code)

### L13. `areEnemies` treats teamless characters as enemies; `normalize` is case-sensitive for unknowns
